# 안정성 계약과 폐기 정책

SooTool을 다른 시스템에 붙여 쓸 때 무엇이 바뀌지 않고 무엇이 바뀔 수 있는지 정한다. 현재 0.x이므로 아래는 1.0에서 확정할 기준이며, 0.x 동안에도 이 기준에 맞춰 변경한다. 아래 항목 중 구조로 확인할 수 있는 것은 `tests/test_contract_invariants.py`가 검사한다.

## 호환을 약속하는 것

|대상|호환 변경|호환을 깨는 변경|
|-|-|-|
|도구 이름과 네임스페이스(`tax.kr_income`)|-|이름 변경, 삭제(폐기 절차를 거친다)|
|입력 인자|선택 인자 추가, 기본값 유지|필수 인자 추가, 이름 변경, 타입 좁힘|
|결과 필드(`outputSchema`)|필드 추가|필드 제거, 타입 변경|
|오류 계약(`code`, `retryable`, CLI 종료 코드)|코드 추가|기존 코드의 의미 변경|
|영수증(`_meta.integrity`의 필드와 해시 규칙)|필드 추가|형식 변경. 이때는 `sootool_version`으로 구분하고 이전 영수증의 재실행 검증을 유지한다|
|정책 파일 형식(헤더, `citations`, 파일 이름 규칙)|선택 헤더 추가|필수 헤더 변경|

응답에는 선언하지 않은 키가 추가될 수 있다. 소비하는 쪽은 모르는 키를 무시해야 한다.

## 약속하지 않는 것

- **계산 결과 값.** 세법과 보험료율이 바뀌면 같은 입력의 결과도 바뀐다. 이는 정책 갱신이며 오류 정정과 구분된다. 과거 시점의 값은 `as_of`로 다시 계산할 수 있고, 어떤 정책으로 계산했는지는 `policy_*` 필드와 영수증에 남는다.
- `trace.steps`의 내용과 단계 이름, `_meta.hints`의 문구, 도구 설명문.
- 선택 설치(`sootool[symbolic]`)로 제공하는 도구의 지원 범위.
- 정확도 등급이 `approximate`(float64)인 도구의 마지막 유효숫자.

## 도구 버전

도구마다 `version`이 있다. 입력이나 결과 구조가 호환되게 바뀌면 부버전, 호환을 깨면 주버전을 올린다. 설명문이나 내부 구현만 바뀌면 올리지 않는다. 영수증의 `tool_version`이 이 값이라서, 재실행 검증은 같은 도구 버전에서만 의미가 있다.

## 폐기 절차

```
폐기 예고 ──── 유예(마이너 2회 또는 6개월 중 긴 쪽) ──── 주버전에서 제거
   │
   ├─ 도구 정의에 deprecated(대체 도구, 제거 예정 버전) 선언
   ├─ 도구 목록 설명, sootool.describe, 응답 _meta.deprecated에 표시
   └─ CHANGELOG의 Deprecated 항목에 기록
```

0.x에서는 마이너 릴리스에서 제거할 수 있지만 같은 유예 기간을 지킨다. 전송 방식과 CLI 옵션도 같은 절차를 따른다. 정책 값의 정정은 폐기 대상이 아니다.

현재 폐기 예고된 항목:

- **SSE 전송(`sse-legacy`).** MCP 사양에서 폐기됐다. Streamable HTTP(`--transport http`)로 옮긴다.
- **기본 프로파일.** 지금은 `full`이며, 이후 주버전에서 `lean`으로 바뀐다. 프로파일을 지정하지 않고 서버를 띄우면 시작 로그에 이 사실이 표시된다. 지금 동작을 유지하려면 `--profile full`을 명시한다.

## 도구를 늘리지 않는 네임스페이스

`engineering`(56개)과 `probability`(30개)는 새 도구를 추가하지 않는다. 버그 수정은 계속하고, 정확도 등급과 입력 한도는 유지한다. 실제 사용 요청이 생기면 그 근거를 이 문서에 적고 해제한다.

## 지원 환경

- Python 3.12 이상, MCP Python SDK `mcp>=2.3,<3`
- 전송: stdio, Streamable HTTP, Unix 소켓(SSE는 폐기 예정)
- 라이브러리(`sootool.sdk`)의 공개 이름: 네임스페이스 객체, `namespaces()`, `Tool`, `Namespace`
