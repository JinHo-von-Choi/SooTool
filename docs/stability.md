# 안정성 계약과 폐기 정책 (1.0 기준안)

이 문서는 1.0 릴리스에서 약속할 호환 범위와 변경 절차의 기준안이다. 아직 0.x 이므로 약속이 아니라 초안이며, 1.0 을
내기 전에 이 문서의 내용을 시험으로 고정하는 것이 조건이다.

## 호환을 약속하는 대상

1. 도구 이름과 네임스페이스(`tax.kr_income` 등). 이름 변경은 폐기 절차를 따른다.
2. 입력 인자의 이름, 타입, 의미. 선택 인자의 추가와 기본값 유지는 호환 변경이다. 필수 인자 추가, 이름 변경, 타입 좁힘은
   호환을 깨는 변경이다.
3. 결과 필드의 이름과 타입(`outputSchema`). 필드 추가는 호환 변경이고 필드 제거와 타입 변경은 호환을 깨는 변경이다.
   응답에는 선언하지 않은 키가 추가될 수 있으므로 소비자는 모르는 키를 무시해야 한다.
4. 오류 계약: 오류 코드(`code`), `retryable` 의미, 종료 코드(CLI). 코드의 추가는 호환 변경이다.
5. 영수증 형식: `_meta.integrity` 의 필드(`tool`, `input_hash`, `result_hash`, `tool_version`, 정책 필드)와 해시 계산 규칙.
   형식이 바뀌면 `sootool_version` 으로 구분하고 이전 영수증의 재실행 검증을 유지한다.
6. 정책 문서 스키마(헤더, `citations`, 버전 파일 이름 규칙).

## 호환을 약속하지 않는 대상

- 계산 결과의 값. 세법과 보험료율이 바뀌면 같은 입력의 결과가 바뀐다. 이는 오류 정정이 아니라 정책 갱신이며, 값의 근거는
  정책 버전(`policy_version`, `as_of`)으로 재현한다. 과거 시점의 값은 `as_of` 로 조회할 수 있다.
- `trace.steps` 의 내용과 단계 이름, `_meta.hints` 의 문구, 도구 설명문.
- 선택 extra 로 제공하는 도구(`symbolic`)의 지원 범위.
- float64 엔진 도구(`exactness=approximate`)의 마지막 유효숫자.

## 도구 버전

각 도구는 `version` 을 가진다. 입력 또는 결과 구조가 호환되게 바뀌면 부버전, 호환을 깨면 주버전을 올린다. 설명문과 내부
구현만 바뀌면 올리지 않는다. 영수증의 `tool_version` 이 이 값이므로 재실행 검증은 같은 도구 버전에서만 의미가 있다.

## 폐기 절차

1. 폐기 예고: 도구 정의에 `deprecated`(대체 도구와 제거 예정 버전)를 선언한다. 도구 목록의 설명과 응답 `_meta` 에 폐기
   사실이 표기된다. CHANGELOG 의 Deprecated 항목에 적는다.
2. 유예: 폐기 예고 후 최소 두 번의 마이너 릴리스 또는 6개월 중 긴 기간 동안 동작을 유지한다.
3. 제거: 주버전 릴리스에서만 제거한다. 0.x 에서는 마이너 릴리스에서 제거할 수 있으나 같은 유예를 지킨다.

전송 방식(예: SSE legacy)과 CLI 옵션도 같은 절차를 따른다. 정책 문서의 값 정정은 폐기 대상이 아니다.

## 동결 정책 (엔지니어링, 확률)

`engineering`(56개)과 `probability`(30개) 네임스페이스는 신규 도구를 추가하지 않는다. 사용 근거(요청, 이슈, 벤치 사례)가
생기면 이 문서에 근거를 적고 해제한다. 기존 도구는 정확도 등급(`exactness`)과 입력 한도를 유지하며 버그 수정은 허용한다.

## 지원 환경

- Python 3.12 이상, MCP Python SDK v2 계열(`mcp>=2.3,<3`).
- 전송: stdio, Streamable HTTP, Unix 소켓. SSE legacy 는 폐기 예고 상태이며 다음 마이너 릴리스에서 제거한다.
- 라이브러리 인터페이스(`sootool.sdk`)의 공개 이름: 네임스페이스 객체, `namespaces()`, `Tool`, `Namespace`.
